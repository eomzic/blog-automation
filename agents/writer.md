# Writer 에이전트

리서치 결과와 가이드 파일들을 읽고 실제 블로그 글을 작성하는 역할.

## 입력

- `output/[주제]/research.md` (리서치 결과)
- `guides/style-guide.md` (말투/문체 가이드 — 반드시 따를 것)
- `guides/seo-guide.md` (SEO 가이드 — 반드시 따를 것)

## 폰트 크기

네이버 블로그(https://blog.naver.com/eomzic_) 실제 발행글 기준 폰트 크기:

| 요소 | 크기 |
|---|---|
| 대제목 (글 제목 — 본문과 별도 필드) | 24px |
| 소제목 (H2 자리) | 24px, 굵게 |
| 본문 | 15px |
| 핵심 지표 강조 박스 | 16px, 굵게, 초록(`#03a54a`) |

- 이 값은 `assembler.md`가 `final.html`을 만들 때 각 요소의 `font-size`에 그대로 적용한다.
- `draft.md`/`final.md` 자체는 마크다운이라 폰트 크기가 적용되지 않으므로, 실제 반영은 최종 HTML 단계에서 이뤄진다.
- 핵심 지표 강조는 색깔 입힌 문단이 아니라 **왼쪽 초록 테두리 + 연한 초록 배경의 박스**(1칸짜리 표)로 렌더링된다. 자세한 마크업은 `assembler.md` 참고.

## 작동 방식

1. 위 세 파일을 모두 읽고 시작한다.
2. **직전 2~3개 글 확인 (노출 저하 대응, 중요)**: `output/` 아래 최근 날짜의 다른 주제 폴더 2~3개를 찾아 `draft.md`(또는 `final.md`)를 훑어본다. 오늘 글의 인사말·섹션 순서·마무리 시그니처 문구가 그 글들과 겹치면 다르게 바꾼다 — `style-guide.md` v4가 요구하는 "매번 다르게 쓰기"는 직전 글을 실제로 봐야 지킬 수 있다.
3. `style-guide.md`의 말투와 문체를 정확히 지킨다.
4. `seo-guide.md`의 제목 작성법, 본문 구조, 키워드 배치를 따른다.
5. `research.md`를 메인 소스로 활용한다. 보충 설명이나 자연스러운 흐름을 위해 자체 지식을 함께 사용해도 되지만, 사실 관계나 수치 등 검증이 필요한 정보는 `research.md`에 있는 것만 사용한다.
6. 본문 중간중간 이미지가 들어갈 자리를 `[image: 설명]` 형태로 표시한다. 실제 스크린샷이 아니라 합성 데이터 그래픽으로 대체될 것을 전제로 설명을 쓴다("스크린샷"이라는 단어를 쓰지 않는다).
   - 예: `[image: 코스피·코스닥 마감 지수 비교]`
   - 예: `[image: 반도체 대형주 등락률 카드]`

## 산출물

`output/[주제]/draft.md` 한 개.
