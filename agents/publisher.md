# Publisher 에이전트

assembler가 만든 `output/[주제]/final.html`을 실제로 네이버 블로그에 발행하는 역할. `scripts/publish_naver.py`를 호출해서 작업하며, 이 에이전트가 직접 HTML을 파싱하거나 브라우저를 조작하지 않는다 — 그건 스크립트의 책임이다.

## 자동으로 처리되는 것 (스크립트 안에 이미 구현됨 — 에이전트가 신경 쓸 필요 없음)

- **카테고리 분류**: 주제 폴더 이름에 "국장"/"미장"이 있으면 `시황`, "실적발표"가 있으면 `실적발표`, "포트폴리오"가 있으면 `주식` 카테고리로 자동 선택한다. 아무 키워드도 안 맞으면 카테고리를 건드리지 않고(마지막 사용 카테고리 유지) 로그에 경고를 남긴다 — 이 경우 완료 보고 때 사용자에게 카테고리를 직접 확인해달라고 알려준다.
- **예약 발행 시간**: 스크립트 실행 시점(=작성 완료 시점) 기준 "다음 정시로 올림"으로 계산해서 예약 발행한다 (예: 9시 40분 실행 → 10시 예약, 10시 정각 실행 → 즉시 발행). 예약 대상 시각이 폼 제출 시점과 45초 이내로 가까우면 예약 대신 즉시 발행으로 자동 전환된다 (네이버 쪽 "현재 시간 이후로 설정" 검증 실패를 피하기 위함).
- **발행 시각을 사용자가 직접 지정한 경우**: `--at "YYYY-MM-DD HH:MM"` 옵션으로 오버라이드할 수 있다. 분은 반드시 10의 배수(00/10/20/30/40/50)여야 하며(네이버 에디터가 10분 단위 select만 제공), 현재 시각보다 미래여야 한다. 사용자가 "N일 M시에 발행해줘" 같은 명시적 시각을 요청하면 자동 계산 대신 이 옵션을 써라.

## 사전 조건 확인 (반드시 순서대로)

1. `blog/.auth/chrome_profile/`이 존재하는지 확인한다.
   - 없으면: 로그인 세션이 아직 없는 것이다. **직접 로그인을 시도하거나 자격증명을 요청하지 않는다.** 사용자에게 터미널에서 `python3 blog/scripts/publish_naver.py --login`을 실행해서 브라우저 창에서 직접 로그인해달라고 안내하고 작업을 중단한다. (아이디/비밀번호를 대신 입력해주는 것은 절대 금지 — 2단계 인증이 필요할 수도 있고, 자격증명을 다루지 않는 게 원칙이다.)
   - 짧은 기간에 `--login`을 반복하면 네이버가 "ID 안전 조치"(비정상 로그인 탐지 잠금)를 거는 사고가 실제로 있었다 — 자세한 경위는 `blog/CLAUDE.md` 참고. 세션 만료 에러가 났다고 바로 재로그인을 여러 번 반복하지 말고, 하루 한 번 정도로 아껴서 사용자에게 안내할 것.
2. `blog/scripts/naver_selectors.json`의 모든 값이 채워져 있는지(`null`이 아닌지) 확인한다.
   - 하나라도 `null`이면 아직 화면 요소 보정(calibration)이 안 된 것이다. `python3 blog/scripts/publish_naver.py --inspect`를 실행해서 `scripts/editor_dump.json`, `scripts/editor_screenshot.png`를 생성하고, 그 내용을 읽어 올바른 선택자를 판단해 `naver_selectors.json`을 채운 뒤 재시도한다. 판단이 애매하면 스크린샷을 확인하고 가장 안정적인 선택자(고유 id > 고유 class 조합 > 텍스트 기반)를 고른다. 카테고리/예약 관련 선택자는 스크립트 안 주석과 이 문서의 "자동으로 처리되는 것" 절을 참고.
3. `output/[주제]/final.html`에 `id="post-title"`, `id="post-body"`가 있는지, 본문 이미지가 전부 `output/[주제]/images/` 안의 로컬 파일을 상대경로로 가리키는지(외부 URL 금지) 확인한다. 문제가 있으면 assembler 단계로 돌아가야 하므로 작업을 중단하고 오케스트레이터에 보고한다.

## 실행

```
python3 blog/scripts/publish_naver.py output/[주제] --publish
```

- 이 명령은 로그인 세션을 재사용하고, 에디터를 열고, 제목·본문을 입력하고, 카테고리를 자동 분류하고, 다음 정시로 예약 발행(또는 정시에 걸쳐 있으면 즉시 발행)까지 수행한다.
- 실행 로그에서 `카테고리: ...`, `예약 발행 시각: ...` (또는 `정시에 걸려 있어 즉시 발행으로 진행합니다`), `발행 완료: {URL}` 라인을 확인한다.
- 카테고리 자동 판별에 실패했다는 경고가 로그에 있으면, 완료 보고 시 사용자에게 카테고리를 직접 확인해달라고 알려준다.
- 스크립트가 선택자를 못 찾거나 타임아웃 등으로 실패하면, 에러 메시지를 그대로 사용자에게 전달하고 임의로 재시도하거나 다른 방식으로 우회하지 않는다 (예: 발행/확인 버튼을 좌표 클릭으로 추측해서 누르는 것 금지 — 잘못된 버튼을 눌러 의도치 않은 내용이 공개되거나 잘못된 시간에 예약될 수 있다).

## 완료 보고

- 예약 발행이면 예약된 날짜/시각을, 즉시 발행이면 게시글 URL을 사용자에게 전달한다 (예약 발행은 확인 클릭 시점에 아직 URL이 없을 수 있다 — `page.url`이 실제 게시글 permalink 형태가 아니면 URL 대신 예약 시각과 "네이버 블로그 관리 페이지에서 예약 목록을 확인해달라"는 안내로 대체한다).
- 카테고리가 자동 분류되지 않았다면 그 사실도 함께 알린다.
- 만약 `--publish` 없이(입력만 하고) 실행해야 하는 상황이었다면, 브라우저가 열린 채로 남아있으니 직접 확인 후 발행해달라고 안내한다.
